# 02 — Improvement Recommendations

Scope and method match [01](01-codebase-overview.md): `main` @ `ac6ccfe`, findings only where the code itself shows a real issue. This codebase is young (first commit 2026-09-17) but unusually disciplined for its age — RLS lock-down, CSP with nonces, magic-byte upload validation, Zod on every write path, 310 passing unit tests, and a lint rule that forbids hardcoded colours/font sizes in components were all already in place before this review started. That shrank the list considerably; several categories in the brief (input validation, access control, N+1 queries, missing indexes) turned up nothing worth reporting after inspection, so they're omitted rather than padded.

Categories checked and found clean, not included above: input validation (Zod on every Server Action and RPC input reviewed), access control (RLS + `revoke all` verified in every migration; server-only Supabase access verified via `import "server-only"` in every `src/server/**` file touched), CV upload handling (magic-byte check, size cap, UUID path, path-traversal guard — [src/server/storage.ts:19-57](../src/server/storage.ts)), secrets in code (none found; `.env*` correctly gitignored except `.env.example`, which holds names only), N+1 queries (the list/detail/dashboard server functions reviewed all batch with `Promise.all` and `.in()` rather than looping), accessibility (labels, `aria-labelledby`, and icon-button `aria-label`s present in every form/table reviewed — a full WCAG pass is Phase 3's job, not re-litigated here).

Two items were **not** checked and are flagged rather than guessed at: `npm outdated` / `npm audit` were not run (both require network access to the npm registry, out of scope without asking first — see finding #7 for the related CI gap); `npm run build` was not run (Google Fonts fetch at build time is a network call).

## Top 5 quick wins

1. **Unbreak the e2e suite** (#8) — one-line locator fixes restore the only automated check that covers whole screens.
2. **Fix the dashboard's duplicate data fetch** (#1) — Med priority, S effort, immediate perf win on the busiest page.
3. **Add `npm audit` to CI** (#7) — closes a gap the codebase's own security baseline already flagged as open.
4. **Pin the local Node version with `engine-strict`** (#4) — stops phantom test failures from wasting anyone's time.
5. **Suppress the two known-intentional lint warnings** (#5), or **decide the fate of the unused `embeddings`/`match_scores` tables** (#3) — both are five-minute cleanups.

## Suggested architecture direction

No rework is justified. The App Router → Server Component/Action → `src/server/**` domain module → single cached Supabase client pattern is consistent everywhere it was checked, correctly keeps all database access server-side, and is already the shape `nextjs-app`/`supabase-db` prescribe for this project. The one gap worth closing structurally is the thin `components/ui/` layer (#2): filling it out with the missing shadcn primitives (`Input`, `Table`, `Card`, `Badge`) before or during Phase 3 will do more for consistency than any styling pass on top of the current hand-rolled markup, and it's a natural fit for "shared styles first, then page by page" in Phase 3's own workflow. No diagram is needed — the flow in [01](01-codebase-overview.md) doesn't change.
